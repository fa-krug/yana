This is a big one. Yana now pairs with a Yana Server that you run yourself, and that server does all the heavy lifting: fetching feeds, running the aggregators, talking to AI providers. Your phone just mirrors the results, which makes the app itself lighter, faster, and easier on your battery.

Adding and tagging feeds now happens on the server's own web page, opened straight from Settings, so there's no more juggling per-source setup screens inside the app. AI got simpler too: pick Apple Intelligence for on-device summaries, or use whatever provider your server is already configured with. Either way, there's nothing to type in and no key to store on your phone anymore.

Pulling to refresh and reloading a single article both got smarter. Instead of waiting out a fixed timer and hoping for the best, Yana now checks in with the server and knows the moment fresh content has actually landed. Pairing with your server runs through the system browser, so passkeys from your iCloud Keychain and any saved passwords work like they should.

The timeline now follows an article's original publish date rather than when it happened to sync, and unread articles always surface after the ones you've already read, so the next thing worth opening is never buried. If you like, turn on an unread count badge for the app icon in Settings.

First time opening the app? A short guided flow walks you through pairing. Updating from an older, fully local version of Yana? You'll see a one-time note explaining what changed and how to get set up with a server.

One more thing worth knowing: since feeds and AI provider keys now live on your server instead of your phone, OPML import and export inside the app are gone, along with on-device provider credentials. Set those up once on the server and you're done.
